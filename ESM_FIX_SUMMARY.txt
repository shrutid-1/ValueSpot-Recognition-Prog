================================================================================
  ESM MODULE RESOLUTION FIX - SUMMARY
================================================================================

PROBLEM:
  Error: ERR_MODULE_NOT_FOUND: Cannot find module 'src/data/seeders/seedService'
  When running: npm run seed

ROOT CAUSE:
  1. Project uses "type": "module" (ES Modules enabled)
  2. Seeder files used relative imports without .js extensions
  3. Original npm script used "npx ts-node" without ESM configuration
  4. Module resolver couldn't find TypeScript files in ESM mode

================================================================================
THE FIX - 4 CHANGES
================================================================================

CHANGE 1: Created .ts-node.json (NEW FILE)
──────────────────────────────────────────
Location: Project root (.ts-node.json)
Purpose: Configure ts-node to use ESM mode with proper module resolution

Key settings:
  - "extends": "ts-node/bases/esm"        ← Use ESM base config
  - "esm": true                           ← Enable ESM mode
  - "moduleResolution": "node"            ← Use Node's ESM resolver
  - "allowImportingTsExtensions": true    ← Allow .ts imports as .js

CHANGE 2: Created tsconfig.seeders.json (NEW FILE)
────────────────────────────────────────────────
Location: Project root (tsconfig.seeders.json)
Purpose: TypeScript compiler config specifically for seeder files

Key settings:
  - "moduleResolution": "node"            ← Proper ESM resolution
  - "esModuleInterop": true               ← Better compatibility
  - Focused on: "include": ["src/data/seeders/**/*.ts"]

CHANGE 3: Updated package.json (MODIFIED)
──────────────────────────────────────────
File: package.json
Section: "scripts"

BEFORE:
  "seed": "npx ts-node src/data/seeders/seed.ts"

AFTER:
  "seed": "node --loader ts-node/esm --no-warnings=ExperimentalWarning src/data/seeders/seed.ts"
  "seed:dev": "node --loader ts-node/esm --no-warnings=ExperimentalWarning src/data/seeders/seed.ts"
  "seed:verify": "node --loader ts-node/esm --no-warnings=ExperimentalWarning src/data/seeders/verify.ts"

Why:
  - "node --loader ts-node/esm" enables proper ESM support
  - "--no-warnings=ExperimentalWarning" suppresses ESM warnings
  - Works with .ts-node.json configuration

BEFORE:
  import { seedDepartments } from './departmentSeeder'

Why .js extension:

  - Node's ESM loader cannot resolve .ts files without help
  - ts-node with --loader can still interpret .ts files
  - This is the standard pattern for ESM TypeScript projects

================================================================================
KEY CONCEPTS
================================================================================

ESM (ES Modules):
  - Native JavaScript module system
  - Requires explicit file extensions in imports
  - Used by modern Node.js and browsers
  - Enabled via "type": "module" in package.json

Module Resolution:
  - Process of finding imported files
  - "bundler" mode: Vite-style resolution (works for build)
  - "node" mode: Node.js resolution (works for runtime scripts)

ts-node:
  - TypeScript runtime for Node.js
  - Without ESM config: Uses CommonJS
  - With ESM config: Supports modern modules
  - Requires --loader flag for ESM support

.js Extension in ESM:
  - Even though files are .ts, must specify .js in imports
  - ts-node loader transpiles .ts when .js is requested
  - Standard pattern for ESM TypeScript projects
