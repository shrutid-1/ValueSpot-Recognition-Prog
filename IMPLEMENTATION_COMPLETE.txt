ARCHITECTURE HIGHLIGHTS
================================================================================

Dependency Order:
  Departments ──────┐
                    └─→ Employees ──┐
  Core Values ──┐                   ├─→ Nominations ──┐
                ├─→ Behaviours ─┐   │                 └─→ Appreciations
                │               └─→ Scenarios
  Projects ─────────────────────────┘
  
  Manager backfill, Project members, and Badge calculation follow

UUID Mapping:
  Mock ID string (e.g., "amit") → Deterministic UUID
  Always produces same UUID across runs
  No collisions between tables
  Enables consistent FK relationships

Error Handling:
  - Logs each operation with counts
  - Continues processing on non-critical errors  
  - Reports all errors in summary
  - Provides debugging context

RLS Compatibility:
  - Uses anonymous key (respects RLS policies)
  - No service role key in frontend
  - Works with existing security policies

USAGE EXAMPLES
================================================================================

First-time seeding:
  $ npm install
  $ npm run seed
  $ npm run seed:verify
  $ npm run dev

Re-running seeding (idempotent):
  $ npm run seed
  # All records marked "Skipped" - no duplicates

Verifying after seeding:
  $ npm run seed:verify
  # Should show all checks PASS

Testing in application:
  $ npm run dev
  # Navigate to http://localhost:5173
  # Check feed, employees, core values pages

Manual badge calculation:
  $ curl -X POST https://your-project.supabase.co/functions/v1/calculate-badges \
    -H "Authorization: Bearer $ANON_KEY" \
    -H "Content-Type: application/json" \
    -d '{"force": true}'
